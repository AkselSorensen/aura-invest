# Aura-Invest — Plan MVP

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Plateforme de suivi d'investissements personnalisé — style Finary. L'utilisateur ajoute ses investissements par catégories, avec images pour les biens physiques. Compte utilisateur + admin.

**Architecture:** Nuxt 3 (frontend + API Nitro) → Neon PostgreSQL. Auth JWT httpOnly cookies. Upload images sur Vercel Blob. Dashboard admin séparé. Dark theme premium.

**Tech Stack:** Nuxt 3, Tailwind CSS v4, GSAP, @iconify/vue (Lucide), Neon PostgreSQL, Vercel Blob (images), Vercel deployment.

**Design System:** Dark theme (bg-dark: #0A0A0F, surfaces: #111118 / #16161F), accent gold (#C9A84C), cartes glassmorphism (backdrop-blur, border-subtle), typographie Inter/Geist, animations GSAP fluides (fade-up, stagger).

## Phase 1 — Setup & Auth

### Task 1: Scaffold Nuxt 3 project
**Files:** `nuxt.config.ts`, `package.json`, `app.vue`, `assets/css/main.css`

- `pnpm create nuxt-app aura-invest` (ou manuel)
- Install deps: `pnpm add tailwindcss @tailwindcss/vite @pinia/nuxt @iconify/vue gsap pg bcryptjs jsonwebtoken`
- Install devDeps: `pnpm add -D @types/bcryptjs @types/jsonwebtoken`
- Config Nuxt avec `@tailwindcss/vite` plugin + `@pinia/nuxt` module
- CSS: `@import "tailwindcss"` puis `@theme` avec couleurs custom (dark, surface, gold, etc.)
- `app.vue` avec `<NuxtPage/>` dans un wrapper dark global

### Task 2: Database setup — Neon PostgreSQL
**Files:** `server/utils/db.ts`, `server/api/auth/setup.post.ts`, `.env`

- Pool Neon avec `pg` (pattern nuxt-neon-backend)
- `DATABASE_URL` dans `.env`
- Table `users` : id, email (unique), password_hash, salt, name, role (user/admin), created_at
- Table `sessions` : id, user_id FK, token (unique), created_at
- Endpoint `POST /api/auth/setup` pour auto-créer les tables

### Task 3: Register endpoint
**Files:** `server/api/auth/register.post.ts`

- POST { email, password, name }
- Validation: email unique, password ≥ 8 chars
- Hash scrypt + salt
- Insert user (role='user' par défaut)
- Créer session token (randomBytes 32 → hex 64)
- Set httpOnly cookie `auth_token`
- Return { success, user: { id, email, name, role } }

### Task 4: Login endpoint
**Files:** `server/api/auth/login.post.ts`

- POST { email, password }
- Chercher user par email
- Vérifier hash avec timingSafeEqual
- Créer session, set cookie
- Return { success, user }

### Task 5: Auth middleware + session check
**Files:** `server/utils/auth.ts`, `server/api/auth/me.get.ts`

- `getCurrentUser(event)` : lit cookie `auth_token`, cherche session, retourne user (sans password_hash/salt)
- `requireAuth(event)` : 401 si pas connecté
- `requireAdmin(event)` : 403 si role ≠ admin
- `GET /api/auth/me` → retourne l'user courant

### Task 6: Login/Register pages UI
**Files:** `pages/login.vue`, `pages/register.vue`, `components/AuthForm.vue`

- Design premium dark : fond deep dark, carte glass centrée, inputs stylés (border-subtle, focus:gold)
- Login : email + password → POST /api/auth/login → redirect /dashboard
- Register : name + email + password → POST /api/auth/register → redirect /dashboard
- GSAP fade-up sur le form
- Liens croisés entre login/register
- Gestion erreurs (email déjà utilisé, mdp invalide)

**Files:** `pages/dashboard.vue`

- Hero chiffres : Patrimoine total (somme value de tous les investissements), Nombre d'investissements, Plus-value latente
- Cartes stats avec compteurs animés GSAP
- Graphique circulaire (CSS/SVG ou Chart.js) : répartition par catégorie
- Liste derniers investissements ajoutés (5 max)
- Bouton "Ajouter un investissement" (CTA gold)

### Task 9: Catégories — DB + API
**Files:** `server/api/categories/setup.post.ts`, `server/api/categories/index.get.ts`, `server/api/admin/categories.post.ts`

- Table `categories` : id, name, slug, icon (lucide name), color, sort_order, created_at
- Setup avec catégories par défaut : Actions/ETF, Crypto, Immobilier, Métaux Précieux, Objets de Collection, Private Equity, Épargne, Autre
- `GET /api/categories` → toutes les catégories (triées par sort_order)
- `POST /api/admin/categories` → admin peut ajouter/modifier des catégories

### Task 10: Investissements — DB + API CRUD
**Files:** `server/api/investments/setup.post.ts`, `server/api/investments/index.get.ts`, `server/api/investments/index.post.ts`, `server/api/investments/[id].get.ts`, `server/api/investments/[id].put.ts`, `server/api/investments/[id].delete.ts`

- Table `investments` : id, user_id FK, category_id FK, name, description, type (physical/financial), quantity, purchase_price, current_value, purchase_date, image_url, notes, created_at, updated_at
- Toutes les routes protégées par `requireAuth`
- `GET /api/investments` → investissements du user connecté (avec JOIN category)
- `POST /api/investments` → créer un investissement
- `PUT /api/investments/[id]` → modifier (vérifier ownership)
- `DELETE /api/investments/[id]` → supprimer (vérifier ownership)
- Filtres: `?category_id=X`, tri par date

### Task 11: Upload images (Vercel Blob)
**Files:** `server/api/upload.post.ts`

- `POST /api/upload` → reçoit FormData avec fichier image
- Upload vers Vercel Blob (`@vercel/blob`)
- Retourne `{ url }`
- Limite 5MB, formats jpg/png/webp
- Protégé par `requireAuth`

## Résumé technique

| **Frontend** | Nuxt 3, Tailwind v4, GSAP, Lucide icons |

| **Auth** | JWT httpOnly cookies, scrypt |
